# Jev のシナリオ

決めた姿を Jev に投げて、何を選び、値をどう答えるかを数える（`scripts/tools/jev_scenarios.gd`）。

```
TYPESAFE_API_KEY=… godot --headless --path . -- --jev-scenarios --repeat=30
```

- `--repeat=R` … 1本につき何回投げるか（既定 30）
- `--fixed-order` … 手の並びを毎回同じにする（既定は毎回混ぜる。ゲームもそうしている）
- `--only=05` … ファイル名がこれで始まるものだけ
- `--judge` … `期待` に失敗が1つでもあれば終わりのコードを1にする（`--check` が使う）

文章の相手は使わない（Jev だけ）。結果は標準出力と `user://jev_bench/scenarios-*.md`。

## 書き方

1ファイル1本。姿は**ゲームと同じ道**（`Inner.of` → `Brain._state`）で文になるので、
ここに書くのは材料だけ。書かなかった欄は空（感情・相手の値は0）。

**感情と相手の値は姿には出ない**（`Inner.of` の `hide_values`）。書いた値は、答えで値がどこへ動くか（写した先）の起点にだけ使う。

| 欄 | 中身 |
|---|---|
| `名前` / `ねらい` | 表に出す見出しと、何を確かめたいか |
| `期待` | 判定する約束（下の「期待」） |
| `あなた` | `名前`・`性格`・`気質`（「外向」「直観」「感情」「知覚」のうち当てはまる語。無い軸は反対側） |
| `感情` | `{"空腹": 45, …}`。言葉は神の紙にある名前で |
| `相手` | `{"ミナ": {"好感": 20, …}}`。ここに書いた相手が「知っている相手」になり、相手への値を訊かれる |
| `持ち物` | `{"木": 6}` |
| `していること` / `今感じていること` | 一行ずつ |
| `今日あったこと` | 帳面の行（`"08:10 入手：木を手に入れる"` `"08:12 ミナに「…」と言われた"` の形） |
| `前に考えたのは` / `前に考えてから` | 前に考えた時刻と、そこから身に起きたこと（行の形は上と同じ） |
| `覚えていること` | 本人が書き直している文章（100字まで） |
| `村人` | 「この世界の言葉」に並ぶ村人の名前（書かなければ自分と相手） |
| `いま` | `{"日": 2, "時刻": "09:30", "座標": [10, 10]}` |
| `手` | 一覧の文の並び。`"木を手に入れる（木 12, 6）"` の形。ゲームが出す文と同じにする（`Brain._name_act` と `_at`）。持ち物で払えない手は、ゲームの一覧にも出ないので書かない。数えるときは座標を落とした名前でまとめる。まとめ方を変えたいときは `{"文": …, "型": …}` |

手に入れかたは世界が始まるときに Jev が決める（`world/tech_tree.gd`）ので、シナリオでは1つに決めて書いている。
いまの10本は **ハンマー＝木×1・石×1**、**家＝木×4・石×2**。

## 期待

`ねらい` は人が読む文、`期待` は機械が判定する約束。**R回の答えをまとめた数**に対して判定する
（Jev は確率で手を引くので、1回の答えでは何も言えない）。判定は表の頭と各シナリオに載る。

```json
"期待": [
  {"手": "木の実を使う（手の中）", "割合": ">=0.3"},
  {"感情": "空腹", "段階": ">=3"},
  {"相手": "ミナ", "値": "好感", "動き": "<0"}
]
```

| 書き方 | 何を見るか | 外したとき |
|---|---|---|
| `{"手": …, "割合": …}` | その手が選ばれた割合（0〜1）。手の名前は表に出る名前（座標を落としたもの） | 警告 |
| `{"感情": …, "段階": …}` | 答えた段階の平均（0〜4） | 失敗 |
| `{"感情": …, "動き": …}` | 答えをゲームと同じ写し方で寄せたとき、渡した値からいくつ動くかの平均 | 失敗 |
| `{"相手": …, "値": …, "段階" か "動き": …}` | 相手への言葉で同じこと | 失敗 |

比べ方は `">=0.5"` `"<=2"` `">0"` `"<0"`、幅なら `"-5..5"`（両端を含む）。

手は引くたびに揺れるので警告に留め、値の向きや段階を外したら失敗にしている——
値が逆を向くなら、問いの形か答えの読み方が壊れている。

いまの10本の期待は、`ねらい` から読める向きだけを書いた最初の案。閾値は実機で流して詰める。

## 実機テスト

単発（ここ）と流れ（`bench/flows/`）を、本物の Jev に順に投げて判定する（`scripts/tools/check_run.gd`）。

```
godot --headless --path . -- --check [--repeat=10] [--only=単発|流れ|名前の頭]
```

1本ずつ別のプロセスで流し、最後に「何が通らなかったか」だけをまとめて出す。
1本でも失敗があれば終わりのコードが1。まとめは `user://jev_bench/check-*.md`。
文章の相手は止めたまま（`--with-text` で使う）。
